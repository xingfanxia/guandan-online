- **Vercel route signature fix — named HTTP method exports** (commit `cf347e8`, shipped 2026-05-21):
  - All 9 `api/*.ts` routes migrated from `export default async function handler(req: Request): Promise<Response>` to named HTTP method exports: `export async function POST(request: Request): Promise<Response>` (or `GET` for read endpoints). Vercel runtime treats default exports as Express-style `(req, res) => void` and silently ignores returned `Promise<Response>` — request hangs until 300s timeout. Production logs showed `WARN: default export returned a Response. The default-export signature is (req, res) => void — returns are ignored`.
  - Cron broke separately on `request.headers.get is not a function` — same root cause (default-export fallback passed a Node IncomingMessage instead of a Web Request). Named-export pattern fixes both.
  - Local verification via `vercel dev` returned 201 in 519ms for the exact create-room payload that was hanging in production (curl + status check post-deploy: `dpl_7fqaoqai0` Ready in 16s).
  - **Future routes MUST use named HTTP method exports.** `export default async function handler` is the trap.
